# STAR Autonomous Engineering V3 — initial release

V3 inventories the complete GitHub tree metadata from a pinned main SHA, ranks allowed small regular files, and sends a bounded list of up to 36 path/size candidates to an explicitly selected model. It validates a one-to-three-stage roadmap with one-to-four existing files per stage. Plans and actual successful planner model and latency are persisted per owner in D1. Selecting a stage transfers instructions and paths into the existing V2 proposal editor; review and separate approvals remain mandatory. Each edit is based on current main, not a stale roadmap SHA. Private Qwen uses the existing authorized Railway gateway; Cloudflare is the default and only explicit Auto enables failover. Provider availability must be verified in the live owner session. No full-source repository audit, cross-repo writes, unrestricted terminal, scheduled background agent, or autonomous merge. Repair still uses bounded failed job metadata. Known PR recovery verifies exact owner job, branch, base and approved bytes, never replays writes. Apply D1 migration 005 before production deployment.

## V3.1 source evidence and model diagnostics
Optional read-only source review at the exact pinned commit, up to four ranked files, maximum 3,000 characters per file and 8,000 total. Excluded/unavailable/sensitive files are not counted as read. Only path, blob SHA, character count and partial/complete flag are persisted in the owner roadmap, not source excerpts. The owner can turn source review off. A fixed harmless model probe tests the explicit selected provider (no fallback), reports measured response latency or HTTP status, and performs no repository writes. It is not a background health monitor. Cross-repo execution and full-source audit remain out of scope.
