# STAR Autonomous Engineering V3 — initial release

V3 inventories the complete GitHub tree metadata from a pinned main SHA, ranks allowed small regular files, and sends a bounded list of up to 36 path/size candidates to an explicitly selected model. It validates a one-to-three-stage roadmap with one-to-four existing files per stage. Plans and actual successful planner model and latency are persisted per owner in D1. Selecting a stage transfers instructions and paths into the existing V2 proposal editor; review and separate approvals remain mandatory. Each edit is based on current main, not a stale roadmap SHA. Private Qwen uses the existing authorized Railway gateway; Cloudflare is the default and only explicit Auto enables failover. Provider availability must be verified in the live owner session. No full-source repository audit, cross-repo writes, unrestricted terminal, scheduled background agent, or autonomous merge. Repair still uses bounded failed job metadata. Known PR recovery verifies exact owner job, branch, base and approved bytes, never replays writes. Apply D1 migration 005 before production deployment.

## V3.1 source evidence and model diagnostics
Optional read-only source review at the exact pinned commit, up to four ranked files, maximum 3,000 characters per file and 8,000 total. Excluded/unavailable/sensitive files are not counted as read. Only path, blob SHA, character count and partial/complete flag are persisted in the owner roadmap, not source excerpts. The owner can turn source review off. A fixed harmless model probe tests the explicit selected provider (no fallback), reports measured response latency or HTTP status, and performs no repository writes. It is not a background health monitor. Cross-repo execution and full-source audit remain out of scope.

## V3.2 persistent stage ledger
Each roadmap stage can create an owner-scoped V2 draft on the current main commit. The stored roadmap, not client-supplied paths, defines the stage scope. A partial unique index prevents duplicate active initial stage drafts. Subsequent stages are gated on earlier merged jobs; draft discard permits regeneration. Progress follows up to two repair descendants and reports a merged rollback as rolled_back. Each action still requires explicit owner review; no background write, auto-merge, deployment claim, or full autonomous task scheduler. Apply migration 006 before deploying. The stage ledger is separate from independent editor tasks.

## V3.3 operations center
Dedicated private scheduled observer reads at most two public GitHub endpoints per 15-minute tick for the latest 20 approved queued/open jobs. D1 observations and heartbeat are separate from authoritative approval, file verification, CI and merge state. No PAT or model token in the Worker. The owner operations panel shows observations, manual provider probe history (last 100), up to 100 owner-entered notes and up to 10 verified public repository metadata entries. Only the original repository is writable. The terminal link opens the existing Railway Agent Runner, not a new command executor. Apply migration 007 before deployment, deploy cloudflare/engineering-monitor/worker.mjs with only STAR_MEMORY D1 binding, disable public URLs, and configure */15 * * * * Cron Trigger. Actual scheduled invocation must be checked from heartbeat; no autonomous editing or auto-merge.

## V3.4 opt-in engineering memory
Roadmap generation may use relevant owner notes only when explicitly enabled. Word overlap ranks at most 100 notes; up to four excerpts, 800 characters each and 2,500 total, are sent as advisory untrusted context to the chosen provider. Only reference IDs, category and excerpt lengths are persisted with the plan; notes cannot expand write scope or approve any action. Deleting a note removes its stored row, not prior model outputs or previously generated plans. Owners can remove registry entries without deleting repositories. No new migration or permission changes.

## V3.5 bounded provider response
Private provider probes request 64 output tokens and enforce a 20-second deadline. Private engineering calls use at most 40 seconds (20 seconds in Auto) and a 1,200-token budget; Cloudflare calls use a 25-second deadline (20 for a probe). Timeouts cover response parsing, report HTTP 504, and record measured failed-probe latency. Explicit Qwen selection never falls back; Auto may fall back on transient failures only, and client cancellation stops further inference. This improves UI resilience, not the remote GPU's performance or availability. Existing service authorization remains unchanged.

## V3.6 observation-assisted reconciliation
If the branch-filtered PR lookup returns no match, V2 can use an owner-scoped observation no older than one hour as a candidate. It fetches the exact PR again through the authenticated bridge, checks the observed head, branch, repository, base and approved full file contents before transitioning the job. An observation never approves or merges a job. No automatic redispatch. UI status polling continues during transient busy state and still fetches executor status if reconciliation fails. Concurrent state changes are re-read rather than overwritten.

## V3.7 release hardening
Railway propagates incomplete client disconnects through the request AbortSignal to the configured upstream model. This limits abandoned inference, subject to upstream support; it does not guarantee GPU cancellation or successful inference. The developer API now requires the executor workflow run to match the original approved base SHA as well as the exact job title and dispatch event before using it for status/merge. Exact-head checks, content verification and explicit approval remain required. No new credentials or write scope.
