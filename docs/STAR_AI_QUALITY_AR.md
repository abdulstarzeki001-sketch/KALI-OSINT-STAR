# STAR AI — طبقة الجودة والمراجعة

## الفحص المحلي

من جذر فرع star-ai-opencode-local وباستخدام Python 3.12:

```bash
python -m unittest -v scripts.test_star_ai_quality
python scripts/star_ai_quality.py audit path/to/config.py path/to/security.py
```

الفحص يحلل AST دون استيراد أو تنفيذ كود المشروع. يخرج JSON بأرقام الأسطر والقواعد دون مقتطفات المصدر. يرفض الملفات غير المنتظمة والكبيرة ويعيد رمز خروج 1 عند وجود نتائج. القواعد مخصصة لمشروع Python حديث غير متزامن؛ استخدام SQLAlchemy المتزامن ليس ثغرة بذاته. الفحص ليس ضماناً لأمان المشروع ولا يغطي جميع أخطاء JWT.

## قياس نموذج GPU

على خادم Ollama المعزول الذي يحتوي النموذج:

```bash
python scripts/star_ai_quality.py benchmark --model qwen3-coder:30b
```

يستدعي محرك Ollama المحلي فقط، دون مفاتيح أو اتصال بخدمات خارجية، ويعرض اسم النموذج وزمن الاستجابة وسرعة توليد الرموز إن أعادها Ollama. المهمة البرمجية مصطنعة وغير حساسة. لا ينفذ الكود المولد.

## مراجع مستقل اختياري

اعرض النماذج المثبتة باستخدام ollama list. مرر اسم نموذج مختلف مثبت فعلياً إلى --reviewer مع الأمر السابق. مثلاً إن كان deepseek-r1:8b مثبتاً:

```bash
python scripts/star_ai_quality.py benchmark --model qwen3-coder:30b --reviewer deepseek-r1:8b
```

هذا يرسل نتيجة التمرين المصطنع لمراجع محلي مختلف ويعرض رأيه، دون منحه أي أدوات. لا يفترض أنه مثبت ولا يقوم بتنزيله. اختلاف الاسم لا يثبت استقلال الأوزان. لا تعتبر رأي النموذج شهادة أمان.

## دورة المراجعة

1. إنشاء اقتراح كود في OpenCode.
2. مراجعة بشرية وفحص AST ثم تشغيل اختبارات المشروع الموثوقة في بيئة غير مميزة ومعزولة، دون أسرار الإنتاج.
3. يفتح المسؤول PR ويراجع CI وSTAR AI Quality.
4. يدمج المسؤول بعد النجاح فقط. لا نشر آلي من هذه الطبقة، ولا تعديل على قواعد حماية الفروع أو Railway.

اختبارات unittest هنا تستخدم بيانات مصطنعة ومحاكاة اتصال النموذج. لا تثبت نجاح الاستدلال الحقيقي. لا تمرر بيانات حكومية أو مفاتيح أو سجلات خاصة للمراجعين.
