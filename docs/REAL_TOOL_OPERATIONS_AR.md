# تشغيل الأدوات فعلياً داخل KALI-OSINT-STAR

## دخول المالك

افتح https://kali-osint-star.pages.dev/#tools بعد تسجيل الدخول إلى Cloudflare Access. كل بطاقات الأدوات تتصل عبر Pages Functions → Service Binding `WORMSTAR_TERMINAL` → Wormstar Worker → حارس الأصل السري → Railway Linux. لا تُرسل مفاتيح Railway أو Cloudflare للمتصفح.

اضغط **فحص تثبيت الجميع**: ستقرأ البطاقات حالة 15 برنامجاً من الملفات التنفيذية الحالية في Railway، وتظهر كلمة «مثبت» إذا كان الملف موجوداً وقابلاً للتنفيذ؛ هذا لا يعني جاهزية قواعد بيانات أو خوادم Windows. اضغط **فحص حقيقي** على بطاقة واحدة لتسجيل نتيجة فحص فعلية، أو **إصدار** عندما يتوفر ثنائي نظام موثوق وسمحت القائمة بأمر إصدار ثابت. النتائج تظهر في البطاقة وتُحفظ آخر 60 عملية على Railway في `.config/wormstar/tools-activity.json`، ويتضمنها `persist backup`.

## الأمر الطبيعي بواسطة STAR AI

من #tools أو #ai اكتب: «افحص أداة Frida» أو «اعرض إصدار NetExec»، ثم اضغط تنفيذ. الخادم يختار أداة واحدة وفحصاً مسموحاً فقط ويشغّله داخل حاوية Railway، دون إدخال نص المستخدم كأمر Bash. إذا كان AI Gateway متاحاً، يمكن طلب شرح لنتيجة الفحص؛ خلاف ذلك تظهر نتيجة حقيقية مع توجيه قواعد ثابتة وتُبيّن الواجهة هذا الفرق. **لا يعتبر توجيه القواعد الثابتة نموذجاً لغوياً مستقلاً**.

لا يسمح التوجيه التلقائي بأهداف شبكة، أو استخراج بيانات اعتماد، أو تشغيل C2 أو implants أو استغلالات أو بدء fuzzing للنواة. تحتاج هذه العمليات إلى بيئة اختبار منفصلة ونطاق مصرح به وموافقة وإدارة موارد وأدلة؛ فحوص النسخة والجرد لا تعني تشغيل كامل قدرات الأداة.

## ما يعمل فعلاً وما لا يعمل

مسارات REST على Railway هي `POST /api/tools/catalog`, `/run`, `/assistant`. هي تعمل فقط مع تفعيل `TERMINAL_EDGE_MODE=enforce` ووجود سرّ أصل خاص يرسله Worker. الواجهة لا تقبل أمر shell عشوائياً أو قيمة هدف. يتم تشغيل الأوامر الثابتة بـ`execFile` من دون shell، خلال 4.5 ثوان وبمخرجات محدودة، وفقط للملفات التنفيذية المملوكة للجذر. المفقود من البرامج سيظهر `not_installed` بصورة صريحة. لا تثبت الحزمة تلقائياً، ولا تعتبر أدوات Linux جميعها متوافقة مع Railway ذات حجم Volume محدود. `STAR AI` لتحليل نتائج الأدوات يعتمد على إعداد مزود الذكاء وسلامة رصيده؛ فحص التثبيت لا يحتاج رصيد AI.

## اختبار إثبات التنفيذ

أضيفت اختبارات Node.js وحاوية Docker ترسل طلبات HTTP حقيقية إلى API الفحص، وتتحقق من رفض الوصول غير المصرّح ومن حفظ النتيجة بعد إعادة تشغيل الخادم. مراقبة GitHub Actions تتأكد أيضاً من عدم وصول الزائر المجهول إلى مسارات أدوات Cloudflare.
