# KALI-OSINT-STAR — دليل مركز أدوات Kali الـ15

## الوظيفة المتاحة حالياً

واجهة **مركز العمليات** ← **مركز الأدوات الفعلية**. يقدم الكتالوج 15 أداة بفحص وجود ملفها التنفيذي الحقيقي على جهاز Kali، وليس نتائج وهمية. تسمح 6 أدوات بإظهار تعليمات المساعدة المحلية باستخدام وسائط مثبتة في الشيفرة، بعد تفعيل الاختيار الصريح. لا توجد أوامر Shell يرسلها المتصفح، ولا تنفيذ استغلال أو جمع كلمات مرور أو إنشاء C2 أو اتصال بأي نظام خارجي في قسم الكتالوج.

| الأداة | وضع التشغيل الآمن |
|---|---|
| Mythic C2 | جرد وجود `mythic-cli` فقط |
| Sliver C2 | جرد وجود `sliver-server` / `sliver-client` فقط |
| Havoc | جرد وجود `havoc` فقط |
| CALDERA | جرد حزمة تنفيذية إن وُجدت؛ المشاريع التي تعمل من `server.py` تحتاج تكاملاً مخصصاً |
| BloodHound CE | جرد وجود `bloodhound` / `bloodhound-python` فقط |
| Certipy | جرد أو Help `certipy-ad -h` |
| Impacket | جرد أو Help `impacket-lookupsid -h` |
| NetExec | جرد أو Help `nxc --help` |
| Rubeus | جرد فقط؛ لا تشغيل Win32 exe |
| Mimikatz | جرد فقط؛ لا الوصول لمواد الاعتماد |
| Ligolo-ng | جرد أو Help `ligolo-proxy -h` |
| Frida | جرد أو Help `frida --help` |
| Ghidra | جرد وجود binary فقط؛ لا تنفيذ GUI |
| AFL++ | جرد أو Help `afl-fuzz -h` |
| Syzkaller | جرد أو Help `syz-manager -h` |

أوامر Help تخضع لمنع افتراضي؛ تفعيلها يحتاج التعديل المحلي التالي في `.env.local`:

```bash
STAR_ENABLE_TOOL_HELP=true
```

ثم إعادة تشغيل FastAPI. **لا تفعل هذه القيمة في خادم عام.** أدوات Help تعمل بأذونات المستخدم المحلي؛ ليست حاوية معزولة، ولذلك يوصى بمستخدم Linux غير متميز وبيئة VM مستقلة. تنفيذ الكتالوج على حساب root غير مستحسن.

## التشغيل

شغّل إعدادات المشروع الموجودة في [LOCAL_OPERATIONS_AR.md](./LOCAL_OPERATIONS_AR.md) وشغّل FastAPI على `127.0.0.1:8000` فقط. شغّل React على `127.0.0.1:5173` وافتح «مركز العمليات» برمز المشغل.

1. اضغط «اتصال وتحديث» باستخدام `STAR_OPERATOR_TOKEN` الذي حفظته محلياً.
2. افتح مركز الأدوات، وابحث عن الأداة المطلوبة. ستظهر حالة تثبيتها الحقيقية في `PATH`.
3. اختر «فحص التثبيت»، أو «تشغيل Help» فقط إذا كان مفعلاً ومتوافراً.
4. أدخل رمز الاعتماد المستقل `STAR_APPROVAL_TOKEN` مع السبب وتأكيد النطاق؛ اعتمد المهمة.
5. اضغط «تشغيل». راقب انتقالها عبر `queued → running → completed/failed`.
6. راجع المخرجات في الواجهة؛ تُحفظ سجلات التدقيق محلياً في SQLite.

## واجهات HTTP

- `GET /api/v1/tooling/catalog` — الأدوات الـ15 وحالات التثبيت وخيارات التشغيل.
- `GET /api/v1/tooling/jobs` — آخر المهام.
- `POST /api/v1/tooling/jobs` — `{ "tool_id": "frida", "action": "inspect" }`.
- `POST /api/v1/tooling/jobs/{id}/approve` — يتطلب الرمز الثاني، سبباً مكتوباً وتأكيداً صريحاً.
- `POST /api/v1/tooling/jobs/{id}/run` — يطلق المهمة بعد الاعتماد.
- `POST /api/v1/tooling/jobs/{id}/cancel` — إلغاء المهمة غير الجارية.

رمز التشغيل في `Authorization: Bearer ...`، ورمز الموافقة في `X-STAR-APPROVAL`؛ لا تضع الأسرار في URL أو ملفات JS. أوامر الـ15 لا تستقبل وسيطات حرة، ولا تنفذ أهدافاً أو IP من المتصفح. الأعمال تُدار عبر ThreadPoolExecutor محدود بعمليتين متزامنتين، وTimeout خمس ثوانٍ، وحجم مخرجات محدود.

## حدود الإنجاز

هذا **تشغيل محلي محدود وحقيقي** ولا يعني أن كل واحدة من أدوات التحكم أو التصعيد أو استخراج بيانات الاعتماد تعمل بقدراتها الهجومية من المتصفح. الأطر الحساسة **جرد فقط**؛ بعضها يحتاج تشغيله في Windows أو بيئات منفصلة. لا يصح اعتبار نجاح اختبارات GitHub Actions دليلاً على وجود الأدوات في جهازك. نتائج التثبيت تأتي من Kali الفعلي فقط عند تشغيل API محلياً.

الاتصال من موقع منشور على Cloudflare بخادم Kali غير مفعّل. لا تكشف منفذ `8000` للإنترنت ولا ترفع `.env.local` إلى GitHub. للسماح بوصول بعيد لاحقاً، أضف Zero Trust/TLS ومصادقة مع صلاحيات دقيقة، ولا تستخدم واجهة عامة لجمع الرموز المحلية.
